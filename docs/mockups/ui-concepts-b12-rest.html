B12 — the rest of the UI

Fifteen screens beyond the primary flow: tools, health, settings and the system screens. Same rules — one hero, a two-row context block, one action, live state instead of help text.

What changed structurally. Diagnostics stops being fourteen rows of numbers and becomes a verdict with the numbers underneath. Calibration becomes one instruction per screen instead of a step counter. Confirmations become sheets over the screen you were on, rather than UIState::CONFIRM — which is what lets the destructive actions stop looking like ordinary buttons.

How a row is written. Left is a noun, right is a value, and neither half is half a sentence. “Then · restarts itself” and “Release · to stop” were both wrong for the same reason: the eye reads the left column as a category, so a verb on the right jars. Sentences move to a full-width note under the heading, instructions move into the action button’s subtitle, and rows keep only numbers, states and times.

Still honest about the data. Everything shown exists: noise stats and motor latency from WeightSensor/DiagnosticsController, storage from the LittleFS partition, sync state from CloudSync, lifetime figures from StatisticsManager. The OTA screens mirror the real staging phases — PSRAM staging, CRC verify, apply — because those are the ones where telling someone not to unplug it actually matters.
